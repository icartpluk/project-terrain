# Inert grid simulation

A standard-library Python model of a generic robot moving through a fictional underground grid. No hardware, Tesla API, network service, or physics engine is used.

## Watch the animation

From the repository root with Python 3.11 or newer:

```sh
python simulation/start.py
```

This generates `results/animation.html` and opens it in your default browser. On Windows, you can instead double-click **START-DEMO.bat** in the repository folder. Extract the repository ZIP first if you downloaded it from GitHub. Python 3.11 or newer must already be installed; no packages, server, or internet connection are needed to run the demo.

If the browser does not open, double-click `results/animation.html` manually. You can keep or share that single HTML file; recipients only need a modern browser, with JavaScript enabled. It does not require Python once generated. If an in-app preview cannot open or scroll the file, open the HTML in your normal browser.

To generate without opening a browser: `python simulation/start.py --no-open`. The launcher always writes to the repository's `results` folder even when run from another folder. The advanced exporter `python simulation/animate.py` still supports seed, map count, fault tick and output options.

The main view keeps Play, Reset, New map, the stop buttons and the robot together. Expand **Playback tools** for Step, speed and seeking. Expand **Choose, save or load a map** for the full map list and files. On narrow screens, scroll sideways within the editing grid. Keyboard users can tab to controls and use arrow keys between editable cells. PAUSED indicates a replay with moves that is currently paused.

Choose **Normal navigation**, **Link loss**, **E-stop**, or **Unauthorized command**, then click **Play**. Use **Pause**, **Step**, **Reset**, the tick slider, and the tick duration selector to inspect the replay. The map shows obstacles, start S, destination G, the traveled path, and robot R. A stopped robot becomes a red `!`, with a persistent **SAFE STOP** banner naming the cause. Text labels distinguish states without relying on color.

With default zero delays, the replay uses `sim.py`'s actual recorded events, including its stop-before-move behavior. It never advances beyond the last recorded event. Reset and scenario selection start a new replay; they do not clear a live robot fault.

The original demo and default fault tick 8 remain reproducible:

```sh
python simulation/animate.py --fault-tick 3 --output results/early-stop.html
```

Click **New map** to advance through 20 embedded seeded maps, or select any map from the **Map** menu. The original demo is always available. The displayed seed identifies each randomized map; all four scenarios share that same map. Changing maps pauses playback and resets the tick while keeping the selected scenario.

The map bank is computed by Python's existing `batch.generate_environment` and `sim.simulate` before export. Nothing is randomly regenerated by the browser. New map cycles back to the first seeded map after the last one. To export a different repeatable bank:

```sh
python simulation/animate.py --seed 42 --maps 30
```

`--maps` accepts 1–100 seeded maps, in addition to the original demo. Seeds run consecutively from `--seed`. Obstacles can disconnect the destination: **NO ROUTE** leaves the robot at its start and disables playback, without claiming a safety stop. **O** markers are inert, traversable foam markers from the existing generator.

Tick 1 stops before the first move. A fault scheduled after arrival is not injected; the display reports GOAL REACHED instead of claiming a safety stop. Randomized batch reports remain available through `batch.py`.

## Experiment with response delays

Expand **Communication and stopping delays**, enter whole ticks from 0 to 100, and click **Apply delays**. Both default to 0. A delayed response shows amber communication/stopping phases and compares predicted latency and extra grid cells with an instant stop. E-stop bypasses communication delay. Applying settings starts a new replay; saved maps preserve nonzero settings. See [TIMING.md](TIMING.md) for the exact model, examples and reproducible commands. This models response timing, not physical braking.

## Trigger a stop during playback

Choose **Normal navigation** and press **Play**. While playback runs, click **Trigger link loss**, **Trigger E-stop**, or **Trigger unauthorized command**. With zero delays, the robot freezes at its current cell, the pending movement timer is canceled, and the red **SAFE STOP** banner names the cause. Nonzero delays show continued movement in amber before the red stop.

Play, Step, and the tick slider remain disabled after a live stop. **Reset** starts a new replay from S. Changing scenario or map, editing a cell, or loading a map also starts a fresh replay and clears the live stop. These are simulated replay actions, not hardware safety resets. The buttons are disabled while paused, before Play, after arrival, when no route exists, or after any safety stop.

The scenario selector still demonstrates scheduled faults at the configured fault tick. Live buttons inject a fault at the currently displayed position instead. Saved map files contain geometry, scheduled fault timing and any nonzero delay settings; live-stop history is not saved.

## Edit a map

Open **Edit this map** below the map. Choose **Toggle obstacle** and click a cell in the editing grid to add or remove an obstacle. Choose **Set destination** and click a cell to move G there (including clearing an obstacle). Start S and boundary cells stay fixed; obstacles cannot replace G. Cells are keyboard-accessible buttons.

Every edit pauses playback, clears the old trail, and recomputes all four scenarios. Press **Play** to watch the new route. A blocked destination reports **NO ROUTE**. **Reset** restarts the edited replay; **Restore map** discards edits and reloads the selected original map. Changing maps or closing/reloading the file also discards edits. The label **Custom map (unsaved)** distinguishes edited maps from the displayed original seeds.

Editing works offline without a server. Exported maps use Python-recorded events; edited maps use an equivalent browser planner and stop model. Automated checks compare its complete results with Python for the embedded maps and custom reachable/unreachable fixtures, at first, intermediate and late fault ticks.

## Save and load layouts

Expand **Choose, save or load a map** and click **Save map** to download `terrain-map.json`. Keep the file in a folder you can find. It contains the current layout and fault tick, including obstacle and destination edits. Your browser may ask where to save it.

Use **Load map** to select that JSON file later. Playback pauses, all four scenarios are recomputed, and the loaded map starts at tick zero using the selected scenario. Files stay on your computer; no upload or server is involved. A loaded layout is a custom map; **Restore map** returns to the selected built-in map. Save again after making further edits.

The version 1 format contains `version: 1`, `grid` (rows of `#.OSG`), and `fault_tick` (integer 1–1000000). Maps must be rectangular, 3–41 cells per side, enclosed by `#`, with exactly one S and G. Files larger than 32 KB are rejected. Optional `communication_delay` and `stopping_delay` fields accept whole ticks from 0 to 100; missing fields default to zero. Saved files contain geometry and timing, not executable code or trusted trial results. Invalid files show a message and preserve the current map; unreachable valid maps load and report **NO ROUTE**.

## Run tests and reports

```sh
python -m unittest discover -s simulation -v
python simulation/sim.py --output results/baseline
python simulation/batch.py --trials 100 --seed 20261030 --output results/randomized
```

Tests cover recorded replay data, stop positions at first/intermediate/final motion ticks, late faults, unreachable goals, repeatability, HTML export, and CLI validation alongside the existing navigation and batch tests.

CI also checks the JavaScript playback controller with Node.js and a minimal DOM stub (no packages). To run that optional developer check locally after generating the animation: `node simulation/test_replay.cjs`. It covers play/pause, stepping, reset, seeking, all three persistent stops, and arrival. It checks controller behavior; browser rendering still requires a visual check.

See [PROTOTYPE.md](PROTOTYPE.md) and [RANDOMIZED.md](RANDOMIZED.md) for the underlying model and reports. All positions and times are idealized grid cells and ticks; the animation demonstrates software behavior, not physical stopping performance. Only inert objects and generic environments are modeled.
